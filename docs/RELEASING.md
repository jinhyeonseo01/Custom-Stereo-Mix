# 릴리즈와 업데이트

## 배포 저장소

- 저장소: https://github.com/jinhyeonseo01/Custom-Stereo-Mix
- 릴리즈: https://github.com/jinhyeonseo01/Custom-Stereo-Mix/releases
- 업데이트 조회: `GET https://api.github.com/repos/jinhyeonseo01/Custom-Stereo-Mix/releases/latest`

앱은 공개 정식 릴리즈를 인증 없이 조회합니다. 현재 버전보다 높은 `vX.Y.Z` 태그와 업로드 완료된 해당 버전의 Windows x64 설치기가 있어야 새 업데이트로 안내합니다. 버전은 숫자로 비교하므로 v1.10.0은 v1.9.9보다 높습니다.

## 배포 절차

1. 변경 사항과 `.github/workflows/release.yml`을 커밋하고 원격 저장소에 푸시합니다.
2. 배포할 커밋에 `vX.Y.Z` 태그를 붙입니다.
3. 해당 태그를 푸시합니다.
4. 저장소의 **Actions → Build and publish Windows installer**에서 진행 상황을 확인합니다.
5. 완료 후 **Releases**에서 설치기와 SHA-256 파일을 확인합니다.

```powershell
git tag -a v1.2.3 -m "Release v1.2.3"
git push origin v1.2.3
```

태그는 소스 변경이 커밋된 뒤 만들어야 합니다. 커밋되지 않은 작업 파일은 릴리즈에 포함되지 않습니다. `v1.2.3-beta`, `v1.2.3.4`, `v01.2.3` 같은 형식은 허용하지 않습니다. 각 숫자는 .NET 어셈블리 버전에 맞게 0..65535 범위여야 합니다.

## Actions 작업

워크플로는 태그가 가리키는 커밋을 체크아웃하고 다음 순서로 실행합니다.

1. 태그 형식 검사 및 버전 추출
2. `global.json`의 .NET SDK와 Node.js 24 준비
3. 오디오·상태·업데이트 회귀 테스트
4. 해시와 제작사 서명을 확인한 Inno Setup 7.1.0 준비
5. `build_installer.ps1 -Version <태그 버전>`으로 Windows x64 설치기 빌드
6. 실제 앱 어셈블리 버전과 태그 일치 확인
7. 설치기 SHA-256 파일 생성 및 Actions 아티팩트 보관
8. 초안 릴리즈 생성, 설치기·체크섬 업로드, 릴리즈 공개

GitHub의 자동 `GITHUB_TOKEN`과 `contents: write` 권한을 사용합니다. 개인 토큰을 코드나 앱에 넣지 않습니다. 저장소·조직 정책에서 이 권한을 제한한다면 해당 Actions 권한을 확인해야 합니다.

Windows x64 단일 작업에서 테스트와 설치기 빌드를 한 번 수행합니다. 체크아웃은 태그가 가리키는 커밋만 가져오며 전체 Git 이력은 받지 않습니다. 릴리즈 노트는 GitHub API가 생성하므로 전체 이력이 필요하지 않습니다. 기본 권한은 읽기이고 게시 작업에만 저장소 쓰기 권한을 부여합니다. checkout 자격 증명은 저장하지 않고, npm 다운로드 캐시를 재사용합니다.

완료된 릴리즈의 파일 이름은 다음과 같습니다.

```text
CustomStereoMix-1.2.3-Setup-x64.exe
CustomStereoMix-1.2.3-Setup-x64.exe.sha256
```

로컬 기본 버전은 `Directory.Build.props`에서 관리합니다. 태그 빌드는 이 기본값보다 태그의 버전을 우선하므로 릴리즈된 앱과 설치기 이름이 일치합니다.

## 실패와 재실행

테스트 또는 빌드가 실패하면 릴리즈를 공개하지 않습니다. 업로드가 실패하면 초안을 유지하므로 같은 Actions 실행을 재시도해 완료할 수 있습니다. 설치기는 Actions 아티팩트에도 14일 동안 보관됩니다.

초안 조회는 인증된 릴리즈 목록 API를 사용하고 페이지를 모두 확인합니다. `/releases/tags/{tag}`는 공개된 릴리즈만 반환하므로 초안 조회에 사용하지 않습니다. 조회 자체가 실패하면 새 초안을 만들지 않으며, 기존 초안은 재사용합니다. 게시 스크립트 변경은 `tests/ReleasePublishing.Tests.ps1`로 생성·재시도·페이지 처리·실패 시 공개 차단을 검증합니다.

워크플로 또는 게시 스크립트를 수정한 경우, 기존 태그의 실행을 재시도해도 해당 태그에 저장된 이전 코드가 사용됩니다. 수정 코드를 포함한 새 커밋·버전 태그로 배포하거나, 기존 Actions 아티팩트를 내려받아 수정된 게시 스크립트로 같은 버전의 초안을 마무리해야 합니다.

이미 공개된 동일 태그의 릴리즈는 수정하거나 설치기를 덮어쓰지 않습니다. 변경한 코드를 배포하려면 새 버전 태그를 만드세요. 예전 버전을 뒤늦게 배포할 때 최신 버전 선택은 GitHub의 날짜·버전 기반 `legacy` 정책을 사용합니다.

## 앱 업데이트 동작

- 화면이 준비된 뒤 실행당 한 번 확인합니다. WebView2 새로고침은 재확인을 반복하지 않습니다.
- 설정의 **업데이트 확인**은 수동으로 다시 확인합니다.
- 정식 버전이며 더 높은 버전이고 설치기가 준비된 경우에만 팝업이 열립니다.
- **나중에** 또는 Esc로 닫을 수 있습니다.
- **변경 사항 보기**는 해당 버전의 GitHub 릴리즈 페이지를 엽니다.
- **설치기 다운로드**는 기본 브라우저에서 검증된 공식 다운로드 링크를 엽니다.
- 자동 다운로드·설치나 실행 중인 앱의 강제 종료는 하지 않습니다.
- 네트워크 조회는 8초 안에 시간 초과 처리하고 오디오 명령을 차단하지 않습니다.
- 종료 시 진행 중인 확인을 취소합니다.
- 공개 릴리즈가 없으면 그 상태를 안내하며 최신 버전이라고 표시하지 않습니다.

업데이트 API에는 설치 버전을 담은 User-Agent가 전송됩니다. 설정·장치 ID·캡처 음성은 이 요청에 포함하지 않습니다.
